# Plan 01-01: Homepage Presentation Baseline

<objective>
Implement the Phase 1 homepage presentation baseline so visitors can read the compact profile/header area and browse stable, readable project cards on desktop and mobile while preserving the simple static HTML/CSS/JS and text-file content model.
</objective>

<requirements>
- HOME-01: Visitor can see a clean profile/header area with comfortable spacing on desktop and mobile.
- HOME-02: Visitor can read each project title without relying on hover-only behavior.
- HOME-03: Visitor can browse project cards in a visually consistent grid where images fit cleanly inside their placeholders.
- HOME-04: Visitor can use the homepage on mobile without overlapping text, crowded controls, or hidden essential information.
</requirements>

<must_haves>
<truths>
- D-01: Header uses a compact centered identity block with better spacing and no overlap.
- D-02: Header includes one short intro line under the role.
- D-03: Social links remain a small icon row.
- D-04: Navigation stays directly under the profile block.
- D-05: Desktop project titles appear on hover and keyboard focus only.
- D-06: Mobile project titles are always visible below the image.
- D-07: Desktop hover/focus treatment uses a clean dark title overlay.
- D-08: Cards show title only; no tags, tools, categories, or extra metadata in Phase 1.
- D-09: Long project titles wrap to two lines and clamp.
- D-10: Keyboard focus reveals the same title overlay as hover.
- D-11: Homepage uses a uniform card grid.
- D-12: Project images use contain behavior with a quiet background so the full image remains visible.
- D-13: Project media areas use landscape 4:3 ratio.
- D-14: Grid uses comfortable medium gaps.
- D-15: Thumbnail size controls are removed by default unless the executor determines they remain genuinely useful after the fixed grid is implemented.
- D-16: Visual direction is a clean dark portfolio refresh.
- D-17: Gold accent is used subtly for active nav, focus, and small highlights.
- D-18: Motion is limited to quiet micro-interactions.
- D-19: Poppins remains the site font with tuned sizing and weight.
- D-20: Cards and controls use small crisp radii.
</truths>
<prohibitions>
- Do not add category sections, filters, or photography galleries in this phase.
- Do not introduce a build step, package manager, framework, CMS, or server dependency.
- Do not add tags/tools/category metadata to project cards.
- Do not crop project thumbnail images to fill cards.
</prohibitions>
</must_haves>

## must_haves

- D-01: Use a compact centered identity block with better spacing and no overlap.
- D-02: Add one short intro line under the role. Keep it brief enough that projects still start quickly.
- D-03: Present social links as a small icon row.
- D-04: Keep the navigation directly under the profile block.
- D-05: On desktop, project titles appear on hover and keyboard focus only.
- D-06: On mobile, project titles are always visible below the image so touch users are not dependent on hover.
- D-07: Desktop hover/focus treatment should be a clean dark overlay with the project title.
- D-08: Cards should show title only. Do not add tags, tools, categories, or extra metadata in Phase 1.
- D-09: Long titles should wrap to two lines and then clamp to avoid uneven card growth.
- D-10: Keyboard focus should reveal the same title overlay as mouse hover.
- D-11: Use a uniform card grid rather than dense gallery or editorial/featured layout.
- D-12: Project images must use contain behavior with a quiet background so the full image fits inside the placeholder.
- D-13: Use landscape 4:3 card media areas.
- D-14: Use comfortable medium gaps between cards.
- D-15: Existing thumbnail size controls are implementation discretion after the redesigned grid is visible; default to removing them if the stable grid makes them unnecessary.
- D-16: Use a clean dark portfolio refresh, preserving the dark identity while improving spacing, borders, typography, image backgrounds, hover states, focus states, and mobile polish.
- D-17: Use the existing warm/gold accent subtly for active nav, focus, and small highlights.
- D-18: Use quiet micro-interactions only: smooth hover/focus overlays and gentle lifts, no flashy animation.
- D-19: Keep Poppins and tune sizing/weight instead of changing the typeface.
- D-20: Use small-radius crisp cards and controls. Avoid very rounded or overly soft UI.

<threat_model>
Security exposure is low because this phase is static UI polish with no new form inputs, backend, auth, or storage. Still apply these mitigations:
- External links created or touched in `JS/userinformation.js` must include `rel="noopener noreferrer"` when `target="_blank"` is used.
- Avoid adding new `innerHTML` for user-controlled text from config/project files; prefer `textContent` for the intro line and card text.
- Do not add remote scripts, new CDNs, or third-party registries.
Blocking threshold: high. No high-severity threats are expected if the mitigations above are followed.
</threat_model>
